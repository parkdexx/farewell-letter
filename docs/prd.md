# PRD — farewell-letter

## 1. 개요
비밀번호를 입력해야만 내용을 볼 수 있는 1페이지 정적 웹사이트. 이별편지 한 통을 담아 GitHub Pages(무료)에 배포한다.

## 2. 목표
- 받는 사람이 URL과 비밀번호를 알아야만 편지를 읽을 수 있다.
- 비용 없이(GitHub 무료 플랜) 배포·유지할 수 있다.
- "비밀번호 보호"가 단순 UI 가리기가 아니라, 저장소 소스를 봐도 실제 내용을 알 수 없는 수준의 보안이어야 한다.

## 3. 핵심 요구사항 (기능)
- 방문자는 비밀번호 입력창만 먼저 본다. 편지 내용은 기본적으로 숨겨져 있다.
- 올바른 비밀번호 입력 시 편지 전문이 화면에 표시된다.
- 틀린 비밀번호 입력 시 "비밀번호가 올바르지 않습니다" 등 일관된 에러만 표시하고, 다른 정보는 노출하지 않는다.
- 편지 내용 작성자(나)는 로컬에서 편지 텍스트를 수정하고 재배포할 수 있어야 한다.

## 4. 디자인 / UI / 톤앤매너
- **전체적인 무드:** 담담하고 차분한 느낌
- **컬러/폰트:** 
  - 배경색 : 우선 ai 추천으로 진행
  - 글자색 : 우선 ai 추천으로 진행
  - 다크모드 : 지원하지 않음
  - 사용하고 싶은 폰트(웹폰트 사용 시 이름) : 우선 ai 추천으로 진행
- **레이아웃:**
  - 전체 화면 배경에 텍스트만
  - 비밀번호 입력창과 편지 화면의 전환 방식 : 페이드인 애니메이션
- **반응형:** 모바일 위주(갤럭시 z flip7 을 대상으로 최적의 환경 제공)
- **참고 레퍼런스:** https://www.huddle.works/

이 섹션이 비어 있으면 지금 구현은 `src/style.css`의 기본 스타일(시스템 폰트, 흰 배경, 왼쪽 정렬 폼)을 그대로 사용합니다. 구체적인 취향이 생기면 이 섹션에 적고 알려주시면 `src/style.css`에 반영합니다.

## 5. 보안 요구사항
- 저장소는 GitHub Pages 무료 배포를 위해 **Public**이어야 하므로, 저장소에 커밋되는 모든 것은 공개된다고 가정한다.
- 따라서 편지 평문은 **어떤 형태로도 git에 커밋되지 않는다.**
- 보호 방식은 클라이언트 사이드 실제 암호화로 구현한다: 비밀번호 기반 키 파생(PBKDF2) + AES-GCM 대칭 암호화(Web Crypto API).
  - 로컬에서 평문 + 비밀번호로 암호문(ciphertext, salt, iv)을 미리 생성해 그 암호문만 커밋한다.
  - 배포된 페이지는 암호문만 로드하고, 방문자가 입력한 비밀번호로 **브라우저 안에서** 복호화를 시도한다.
  - 비밀번호가 틀리면 AES-GCM 인증 태그 검증이 실패해 복호화 자체가 불가능하다 (단순 if문 우회가 통하지 않음).
- 비밀번호는 어떤 파일에도, 어떤 커밋에도, GitHub Actions 로그에도 남지 않는다. 로컬에서 암호화할 때만 사용자가 직접 입력한다.
- **보안 한계 (명시적으로 인지할 것):** 저장소가 공개되므로 salt/iv/반복 횟수/암호문이 모두 공개되며, 정적 사이트 특성상 오프라인 무차별 대입 공격을 막을 방법(rate limiting 등)이 없다. 실질적 방어는 비밀번호(패스프레이즈)의 엔트로피뿐이다. → 짧은 단어/생일 조합이 아니라 긴 문장형 패스프레이즈를 사용한다.

## 6. 기술 스택
- 빌드 도구 없이도 되지만, 개발 편의를 위해 **Vite + Vanilla JS** 사용 (프레임워크 없음, 별도 UI 라이브러리 없음).
- 암호화는 브라우저/Node 내장 **Web Crypto API**만 사용 (외부 crypto 라이브러리 의존성 없음).
- 배포는 **GitHub Actions → GitHub Pages** (별도 유료 서버/서비스 없음).

## 7. 디렉토리 구조 (요약)
```
content/letter.local.txt   # 편지 평문 (gitignore, 절대 커밋 안 됨)
scripts/encrypt.mjs         # 평문+비밀번호 -> src/letter.enc.json 생성 (로컬 전용 실행)
src/letter.enc.json         # 커밋되는 유일한 편지 관련 파일 (암호문)
src/crypto.js, src/main.js  # 브라우저 복호화 로직 + UI
.github/workflows/deploy.yml # 빌드 후 Pages 자동 배포
```
자세한 구조/역할 분리는 `CLAUDE.md` 참고.

## 8. 사용자 흐름
1. (작성자) `content/letter.local.txt`에 편지 작성 → `npm run encrypt`로 비밀번호 입력 → `src/letter.enc.json` 생성 → git commit & push.
2. GitHub Actions가 자동으로 빌드 후 GitHub Pages에 배포.
3. (작성자) 받는 사람에게 배포된 URL과 비밀번호를 별도 채널(문자 등)로 전달.
4. (받는 사람) URL 접속 → 비밀번호 입력 → 편지 확인.

## 9. 비범위 (하지 않는 것)
- 서버/DB, 로그인 계정 시스템, 여러 편지/멀티 유저 지원.
- 비밀번호 찾기/재설정 기능 (비밀번호를 잊으면 복호화 불가 — 의도된 동작).
- 접속 로그, 조회 여부 알림 등 추가 기능.
